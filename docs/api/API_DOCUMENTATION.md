## Общая информация

### Базовый URL
```
http://localhost:3000
```
(Порт настраивается через переменную окружения `SERVER_PORT`)

### Формат данных
- Все запросы и ответы используют формат JSON
- Content-Type: `application/json`
- Кодировка: UTF-8

### Сессии
Приложение использует cookie-based сессии. После успешной авторизации сессия сохраняется в cookie и автоматически отправляется с каждым запросом.

### Роли пользователей
- `Admin` - Администратор (полный доступ)
- `Manager` - Менеджер (управление пользователями и данными)
- `Instructor` - Инструктор (доступ к своим данным)
- `User` - Обычный пользователь (ограниченный доступ)

### Статусы пользователей
- `New` - Новый пользователь (требует регистрации)
- `Active` - Активный пользователь
- `Deactive` - Деактивированный пользователь

## Аутентификация

Большинство endpoints требуют аутентификации через сессию. Endpoints, требующие авторизации, помечены middleware `IsSignIn`. При отсутствии авторизации возвращается статус `401` с текстом `"require auth"`.

`IsSignIn` на каждом запросе сверяет пользователя с базой: сессия действует, только пока аккаунт существует и находится в статусе `Active`. Поэтому блокировка аккаунта, возврат в режим приглашения или удаление сразу обрывают уже выданные cookie. Роль в сессии тоже обновляется из базы, так что изменение роли применяется немедленно.

## Пользователи (`/api/user`)

### `GET /api/user/is_auth`

Проверка статуса аутентификации текущего пользователя.

**Авторизация:** Не требуется

**Описание:** Проверяет, авторизован ли пользователь и активен ли его аккаунт. Обновляет данные сессии.

**Параметры запроса:** Отсутствуют

**Ответы:**

**200 OK** - Пользователь авторизован и активен
```json
{
  "status": true,
  "user_id": 1,
  "user_role": "Admin"
}
```

**200 OK** - Пользователь не авторизован
```json
{
  "status": false,
  "user_id": 0,
  "user_role": "User"
}
```

**Пример использования:**
```bash
curl -X GET http://localhost:3000/api/user/is_auth \
  -H "Cookie: connect.sid=..."
```

- `password` (string, обязательный) - Пароль пользователя

**Ответы:**

**200 OK** - Успешная авторизация
```
(пустое тело)
```

```json
[
  {
    "value": "...",
    "context": [...],
    "message": "..."
  }
]
```

### `POST /api/user/edit`

Редактирование учётных данных пользователя.

**Авторизация:** Требуется (`IsSignIn`)

**Требования к роли:** `Admin` или `Manager`. Менеджер не может редактировать пользователя с ролью `Admin` и не может выдать роль `Admin`.

**Описание:** Меняет логин, роль и привязку к инструктору. Пароль и статус не затрагивает.

**Тело запроса:**
```json
{
  "user_id": 2,
  "login": "newlogin",
  "role": "Manager",
  "instructor_id": 1
}
```

**Параметры:**
- `user_id` (number, обязательный) - ID пользователя
- `login` (string, обязательный) - Новый логин, не может быть пустым и должен быть уникальным
- `role` (string, обязательный) - `Admin` | `Manager` | `Instructor` | `User`
- `instructor_id` (number, обязательный) - ID инструктора, `0` снимает привязку

**Ответы:**

**200 OK** - Данные обновлены

**400 Bad Request:**
- `"login_empty"` - Логин пустой
- `"login_exists"` - Логин уже занят другим пользователем
- `"user_not_found"` - Пользователь не найден
- `"instructor_not_found"` - Инструктор не найден
- `"self_role_change"` - Попытка изменить собственную роль

**403 Forbidden** - Недостаточно прав

**Пример использования:**
```bash
curl -X POST http://localhost:3000/api/user/edit \
  -H "Content-Type: application/json" \
  -H "Cookie: connect.sid=..." \
  -d '{
    "user_id": 2,
    "login": "newlogin",
    "role": "Manager",
    "instructor_id": 0
  }'
```

### `PUT /api/money/instructor/:id/addMoney`

Пополнение баланса инструктора.

**Авторизация:** Требуется (`IsSignIn`), роль `Admin` или `Manager`

**Описание:** Фиксирует оплату от инструктора: уменьшает его долг (`Instructor.price`) на указанную сумму, создает запись в истории операций и разносит оплату по файлам (`File.paid` + записи `FilePayment`).

**Параметры пути:**
- `id` (number, обязательный) - ID инструктора

**Тело запроса:**
```json
{
  "money": 100.50,
  "files": [
    {"id": 12, "sum": 80.00},
    {"id": 13, "sum": 20.50}
  ]
}
```

**Параметры:**
- `money` (number, обязательный) - Сумма оплаты (должна быть > 0)
- `files` (array, необязательный) - Ручное распределение оплаты по файлам
  - `id` (number) - ID файла, должен принадлежать этому инструктору
  - `sum` (number) - Сумма, зачитываемая за файл; должна быть > 0 и не больше остатка `fallaf_price - paid`
  - Если массив не передан или пуст, оплата разносится автоматически: от самого старого неоплаченного файла к самому новому
  - Сумма всех `sum` не может превышать `money`; неразнесённый остаток остаётся авансом (уменьшает долг, но ни за каким файлом не закреплён)

**Ответы:**

## Коды ошибок

### HTTP статус коды

- **200 OK** - Успешный запрос
- **400 Bad Request** - Ошибка валидации данных или некорректный запрос
- **401 Unauthorized** - Требуется авторизация
- **403 Forbidden** - Недостаточно прав доступа
- **404 Not Found** - Ресурс не найден
- **500 Internal Server Error** - Внутренняя ошибка сервера

### Текстовые сообщения об ошибках

- `"require auth"` - Требуется авторизация (401)
- `"Forbidden"` - Недостаточно прав (403)
- `"not_found"` - Ресурс не найден (404)
- `"user_not_found"` - Пользователь не найден или неактивен (400)
- `"password_invalid"` - Неверный пароль (400)
- `"error name"` - Ошибка валидации имени (400)
- `"error money"` - Ошибка валидации суммы (400)
- `"error id"` - Ошибка валидации ID (400)
- `"error price"` - Ошибка валидации цены (400)
- `"not found instructor"` - Инструктор не найден (400)

### Формат ошибок валидации (io-ts)

При ошибках валидации возвращается массив объектов с описанием ошибок:

```json
[
  {
    "value": "некорректное значение",
    "context": [
      {
        "key": "login",
        "type": {
          "name": "string"
        },
        "actual": "некорректное значение"
      }
    ],
    "message": "Invalid value..."
  }
]
```

## Безопасность

### Разграничение доступа

1. **Управление пользователями:**
   - Endpoints `/api/user/all`, `/add`, `/edit`, `/set-password`, `/reset-invite`, `/enable`, `/disable`, `/delete` доступны ролям `Admin` и `Manager`
   - Менеджер не может редактировать пользователя с ролью `Admin`, менять ему пароль, сбрасывать или блокировать его, а также не может выдать роль `Admin` - это закрывает поднятие прав через чужой аккаунт
   - Нельзя изменить собственную роль, вернуть себя в режим приглашения и заблокировать себя

2. **Финансовые endpoints:**
   - Все endpoints в `/api/money` закрыты middleware `IsSignIn`, без сессии возвращается `401 "require auth"`
   - Изменяющие операции (добавление и удаление инструкторов и файлов, приём оплат, правка цен, расчёты с программистом) доступны только ролям `Admin` и `Manager`, остальным - `403 "Forbidden"`
   - Роль `Instructor` имеет доступ только на чтение: `GET /api/money/files` отдаёт лишь его собственные файлы и без поля `dev_price`, `GET /api/money/instructors` - только его собственную запись
   - Роль `User` не имеет доступа к `/api/money` вообще
   - `GET /api/free-kassa/get-pay-url` закрыт `IsSignIn`

### ⚠️ Важные замечания

1. **Хеширование паролей:**
   - Пароли хранятся в хешированном виде с использованием библиотеки `password-hash`
   - При регистрации пароль автоматически хешируется

2. **Сессии:**
   - Сессии хранятся в базе данных через `PrismaSessionStore`
   - Время жизни сессии: 7 дней
   - Cookie не защищены флагом `secure` (для разработки)

3. **Валидация данных:**
   - Все входные данные валидируются через библиотеку `io-ts`
   - При ошибках валидации возвращается детальное описание проблемы

4. **FreeKassa:**
   - Webhook endpoint не проверяет подпись запросов
   - Необходимо добавить проверку подписи `SIGN` перед обработкой платежей
