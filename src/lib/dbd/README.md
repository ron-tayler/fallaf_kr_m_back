# Модуль dbd — работа с лентой КЛУБ-У (.dbd)

Изолированный модуль для файлов скоростемерной ленты формата СУД (`.dbd`,
контейнер `ÿRPA`): расшифровка/шифрование, разбор данных в модель и правки
с байт-точной сборкой. Без привязки к API.

Зависимостей нет — используется встроенный модуль Node.js `crypto`.

## Состав

```
src/lib/dbd/
├── DbdCrypto.ts       расшифровка / шифрование контейнера
├── DbdTape.ts         разбор открытого .dbd в модель (только чтение)
├── DbdTapeEditor.ts   правки данных с сохранением размера (байт-точно)
├── cli.ts             CLI для ручной проверки crypto
├── index.ts           реэкспорт
└── README.md          этот файл
```

## 1. Шифрование — `DbdCrypto`

Схема вскрыта реверс-инжинирингом `USK.dll` / `SudLite.exe` (класс `TCipherAES`).

| Параметр   | Значение                                                        |
|------------|-----------------------------------------------------------------|
| Алгоритм   | **AES-256-CBC**                                                 |
| Ключ       | `15F4CFD6-40A6-49C1-99C8-5926D244` (первые 32 байта GUID-строки) |
| IV         | `6d 33 31 21 34 30 12 61 44 62 38 37 51 31 7e 35` (строка `m31!40…`) |
| Дополнение | нулевыми байтами до кратности 16                                |

Контейнер зашифрованного `.dbd`:

```
0x000  264   заголовок (открытый текст, копируется как есть)
0x108   4    сигнатура  FF 52 50 41  ("ÿRPA")
0x10C   8    размер расшифрованного файла, uint64 little-endian
0x114  ...   AES-256-CBC шифртекст
```

```typescript
import {DbdCrypto} from "@/lib/dbd"
const c = new DbdCrypto()
c.isEncrypted(buf)   // boolean
c.decrypt(buf)       // Buffer: зашифрованный .dbd -> открытый
c.encrypt(buf)       // Buffer: открытый .dbd -> контейнер
```

`decrypt`/`encrypt` проверены побайтово на реальном файле (обе стороны точные).

## 2. Разбор данных — `DbdTape`

Разбирает открытый (расшифрованный) `.dbd` в модель. Хранит исходный буфер и
накладывает семантику поверх — это делает обратную сборку без потерь.

```typescript
import {DbdTape} from "@/lib/dbd/DbdTape"
const model = new DbdTape(plain).parse()
// model.minutes — маркеры минут (день/час/минута)
// model.seconds — посекундная шкала
```

Поля секунды (`TapeSecond`):

| Поле                          | Смысл                                        |
|-------------------------------|----------------------------------------------|
| `day/hour/minute/second`      | время кадра                                   |
| `speed`                       | скорость, км/ч                                |
| `speedLimit`                  | ограничение / Vдоп, км/ч                      |
| `pressureTM/UR/TC`            | давления ТМ / УР / ТЦ, кгс/см² (шаг 0.04)      |
| `coord`                       | координата, метры                             |
| `discrete`                    | младший байт маски дискретных сигналов        |
| `events[]`                    | события (записи 0x8F)                         |
| `items[]`                     | все мелкие записи группы, включая неизвестные («песочница») |
| `offset`, `items[].offset`    | абсолютные смещения в буфере                   |

Известные параметры декодируются в удобные поля; всё, что пока не разобрано,
доступно как сырые записи `items` (hex + смещение) — для правки «методом тыка».

## 3. Правки — `DbdTapeEditor`

Правит открытый буфер, сохраняя общий размер файла за счёт FF-заполнителя
(при удлинении «съедает» соседние `0xFF`, при укорачивании — дописывает). Байты
вне правок не меняются, поэтому после `encrypt` файл совпадает с исходным
с точностью до внесённых изменений.

Адресация — по **индексу кадра** (позиция в `model.seconds`), а не по времени:
время секунды в ленте неуникально (регистратор пишет по нескольку кадров в одну
секунду, особенно на стоянке), поэтому индекс — единственный надёжный адрес.
Он стабилен: FF-сплайс не меняет порядок и число кадров.

```typescript
import {DbdTapeEditor} from "@/lib/dbd/DbdTapeEditor"

const ed = new DbdTapeEditor(plain)
ed.setPressure(i, "TC", 1.56)          // давление ТЦ в кадре #i
ed.setDiscrete(i, 0x0c)                // маска дискрет
ed.dropEvents(i)                       // удалить события кадра
ed.setFrameByte(i, "speed", 60)        // байт кадра: speed (+3) / speedLimit (+5)
ed.setRawItem(i, itemIndex, "2708")    // сырая правка записи (песочница), та же длина
const out = ed.result()                // открытый .dbd с правками
```

Проверено: воспроизведение правки эталонного онлайн-редактора
(08:02:50–52) даёт **байт-идентичный** поток записей и точный круговой цикл
`decrypt → правка → encrypt → decrypt`.

## Типовой сценарий

```typescript
import {DbdCrypto, /* */} from "@/lib/dbd"
import {DbdTapeEditor} from "@/lib/dbd/DbdTapeEditor"

const c = new DbdCrypto()
const plain = c.decrypt(readFileSync("game.dbd"))
const model = new DbdTape(plain).parse()
const i = model.seconds.findIndex(s=>s.hour === 8 && s.minute === 2 && s.second === 51)
const ed = new DbdTapeEditor(plain)
ed.setPressure(i, "TC", 1.56)
writeFileSync("game_fixed.dbd", c.encrypt(ed.result()))
```

## Статус и границы

- Надёжно декодируются подтверждённые параметры (время, скорость, ограничение,
  координата, давления ТМ/УР/ТЦ, дискреты, события).
- Остальные записи потока (~256 типов) доступны как сырые `items` — их смысл
  выясняется «песочницей»: правим байт → открываем в СУД-У → смотрим отличие.
- Блок КЛУБ-параметров (номер локомотива, депо, машинист, бандажи и т.п.) и
  список ситуаций пока не разобраны в модель — на следующих итерациях.

## CLI (проверка crypto)

```bash
npx ts-node -r tsconfig-paths/register src/lib/dbd/cli.ts decrypt in.dbd out.dbd
npx ts-node -r tsconfig-paths/register src/lib/dbd/cli.ts encrypt in.dbd out.dbd
```
